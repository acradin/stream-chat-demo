# 버튼으로 만드는 AI 라이브 채팅 데모

## 현재 앱: 버튼 캡처 / 실시간 화면을 선택하는 데스크톱 오버레이

**Windows 설치본:** `dist/StreamChat-Setup-0.4.0-x64.exe` — Python 없이 설치하고 시작 메뉴의 **Stream Chat**을 열면 네이티브 오버레이가 바로 뜹니다. [설치·연결 안내](INSTALLER.md).

Figma 기반 tiki 오버레이의 **사용 방식**에서 **버튼 캡처 모드 / 실시간 화면 모드**를 고릅니다. 버튼 모드는 주 모니터 한 장을 `gpt-6-astra`로 분석합니다. 실시간 모드는 사용자가 선택한 창을 연속 관찰하고 OpenAI Realtime으로 채팅할 순간을 판단합니다. 원형 버튼으로 생성하고 톱니에서 방송 링크·단축키·설명·페르소나·사용량을 확인합니다. 브라우저 접속은 필요 없습니다.

현재 프로젝트에서는 **`start_desktop.cmd` 더블클릭**으로 로컬 백엔드와 오버레이를 함께 시작합니다. **AI API 키는 운영자의 `backend/.env`에만 둡니다.** [Mac 실행·설치](apps/desktop/mac/README.md), [Linux X11 실행·빌드](apps/desktop/linux/README.md)도 제공합니다. 설치본은 운영 중인 백엔드에 연결하는 클라이언트이며 계정 로그인은 데모 범위에서 제외합니다. [두 모드 테스트 방법](DESKTOP.md)과 [운영자 서버·키 설정](BACKEND.md)을 확인하세요.

**공개 웹:** [tiki-chat.duckdns.org](https://tiki-chat.duckdns.org/) — 팀원 React 웹 프론트를 AWS에 배포했습니다. 공개 화면은 예시 채팅을 만드는 Mock 체험이며 AI 비용이나 방송 전송이 발생하지 않습니다. 같은 주소의 데스크톱 API는 서비스 인증을 요구합니다.

| 폴더 | 담당 영역 |
|---|---|
| `apps/desktop/` | 데스크톱 UI, 화면 캡처, 전역 단축키 |
| `apps/web/` | 팀원 React/Vite 프론트 통합본과 기존 로컬 웹 데모 ([실행 안내](apps/web/README.md)) |
| `backend/` | 서비스 HTTP API, 계정별 사용량, 공통 페르소나, AI provider |
| `deploy/aws/` | 새 AWS 계정용 EC2·HTTPS·서버 설치 및 검증 도구 ([안내](AWS.md)) |
| `experiments/` | 기존 자동 영상 분석·리플레이·합성 샘플 |
| `tests/` | 공통·데스크톱·웹·기존 실험 회귀 테스트 |
| `runs/` | 로컬 설정·사용량·실험 결과 (Git 제외) |

Figma 페르소나 6종과 기존 덤덤한 드립러의 말투·예시는 `backend/personas.py`에서 관리합니다. 짧은 반응, 자연스러운 반말, 반복 회피 지침을 적용했습니다. 치지직 공식 API 인증과 운영자용 한 건 전송 CLI는 [치지직 연결 안내](CHZZK.md)를 확인하세요. 실제 방송 전송에는 개발자 앱 설정과 방송 계정 인증이 필요합니다.

아래는 **기존 웹 텍스트 데모**의 실행 안내입니다. 웹 데모는 기존 Gemini/Mock 계약을 유지하며, 새 OpenAI 스크린샷 흐름은 데스크톱에서 사용합니다.

저장소: [acradin/stream-chat-demo](https://github.com/acradin/stream-chat-demo)

**개발을 이어받는 팀원은 [개발 인수인계 문서](HANDOFF.md)부터 확인하세요.** 웹사이트와 데스크톱 앱의 작업 범위, 재사용할 생성 코드, 로컬 API 계약, 다음 개발 순서를 정리했습니다.

**페르소나를 고르고 방송 정보를 적어두면, 버튼을 누를 때마다 그 캐릭터의 짧은 한국어 채팅을 만듭니다.** 웹 서버는 `python -m apps.web`으로 실행합니다. 방송자가 타이밍을 정하고, 텍스트 모델은 선택한 페르소나와 방송 정보를 바탕으로 한 줄을 작성합니다. 매번 반응 종류나 상황 태그를 고를 필요가 없습니다.

이 모드에는 영상·소리 인식이나 자동 `WAIT` / `REACT` 판단이 없습니다. 화면은 본인 컴퓨터에서 실행하는 실험용 패널이며, 생성한 채팅도 이 패널에 표시됩니다. 방송 플랫폼에 실제로 전송하는 기능은 다음 단계입니다.

## 화면만 먼저 체험하기 — 정적 mock 데모

`apps/web/demo/`에는 API 키와 Python 패키지 설치 없이 버튼 흐름을 체험할 수 있는 정적 데모가 있습니다. 프로젝트 폴더에서 Python의 기본 HTTP 서버를 실행합니다.

```bash
python -m http.server 8000 --directory apps/web/demo
```

같은 컴퓨터에서 [http://127.0.0.1:8000](http://127.0.0.1:8000)을 열고 **페르소나**를 고르세요. **방송 정보** 입력란은 선택 사항입니다. 설정한 뒤에는 **드립 만들기** 버튼만 누르면 됩니다. 함께 제공한 합성 테스트 영상이나 본인의 로컬 영상을 보며 누를 수 있습니다. 로컬 영상은 브라우저에서만 재생되며 업로드되지 않습니다.

이 정적 화면은 **실제 AI가 연결되지 않은 체험 데모**입니다. 페르소나별로 준비한 예시 문장을 선택하고 650ms를 인위적으로 기다립니다. 방송 정보는 버튼을 누른 시점의 페르소나와 함께 체험 기록에 담지만, 문장을 고를 때 그 내용을 해석하지는 않습니다. 화면에 표시되는 시간은 설정한 대기와 브라우저 처리 시간이며 AI 성능 수치가 아닙니다. 방송 플랫폼 전송 기능도 포함하지 않습니다.

실제 텍스트 모델을 연결하거나 서버의 요청·표시 로그를 측정하려면 아래의 `apps/web/server.py` 모드를 실행하세요.

## 가장 먼저 실행하기

저장소를 본인 컴퓨터로 내려받은 뒤 프로젝트 폴더에서 실행합니다. 이 저장소는 비공개이므로 GitHub 접근 권한이 있는 계정으로 인증해야 합니다.

```bash
git clone https://github.com/acradin/stream-chat-demo.git
cd stream-chat-demo
```

GitHub의 **Code → Download ZIP**으로 내려받았다면 압축을 푼 폴더에서 터미널을 열어도 됩니다.

Python 3.10 이상이 설치된 환경에서 다음 명령을 실행하세요.

```bash
python -m pip install -r requirements.txt
python -m apps.web --provider mock --output runs/manual_mock
```

서버를 실행한 **같은 컴퓨터의 브라우저**에서 [http://127.0.0.1:8765](http://127.0.0.1:8765)를 엽니다. 터미널은 실행한 상태로 두세요. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 다시 실행할 때는 `runs/manual_mock_2`처럼 새로운 결과 폴더를 지정합니다.

수동 모드는 FFmpeg를 호출하지 않습니다. 브라우저에서 영상 없이도 버튼을 누를 수 있고, 필요하면 로컬 MP4를 골라 옆에서 재생할 수 있습니다. 선택한 파일은 브라우저의 로컬 파일 URL로 재생하며 서버나 모델에 업로드하지 않습니다.

**Mock은 동작 확인용입니다.** 선택한 페르소나에 맞춰 `[MOCK]`로 표시된 미리 정한 한국어 문장을 반환하고 기본 0.2초를 인위적으로 기다립니다. 입력한 방송 정보는 기록에 남지만 문장 생성에 해석해 사용하지 않습니다. 이 시간은 실제 AI의 속도가 아닙니다.

## 버튼 사용법

1. **페르소나**를 고릅니다. 선택한 캐릭터가 채팅의 성격과 말투를 정합니다.
2. 필요한 경우 **방송 정보**에 주제, 방송인의 별명, 방송 분위기, 진행 배경 등을 적어둡니다. 여러 줄로 최대 1,000자까지 입력할 수 있고 비워두어도 됩니다. 예: `별명은 민트. 오늘은 공포 게임 첫 플레이. 게임을 함께 배우는 편한 분위기의 방송.`
3. 원하는 순간에 **드립 만들기** 버튼을 누릅니다. 페이지에 포커스가 있고 입력란에서 글을 쓰는 중이 아니라면 `Space`로도 생성할 수 있습니다.
4. 생성한 채팅과 버튼 입력 후 표시까지의 시간을 확인합니다. 선택한 페르소나와 방송 정보는 유지되므로 다음에는 버튼만 누르면 됩니다. 정보가 바뀌면 입력란을 수정하세요.

| 페르소나 | 채팅 스타일 | API 값 |
|---|---|---|
| 장난꾸러기 친구 | 친구처럼 가볍게 장난치며 분위기를 풀어주는 한 줄 | `witty_friend` |
| 다정한 응원단 | 부담 없이 응원하고 편안하게 말을 건네는 한 줄 | `warm_supporter` |
| 과몰입 해설러 | 에너지 있게 분위기를 띄우는 해설풍 한 줄 | `hype_commentator` |
| 덤덤한 드립러 | 짧고 담백한 말투로 웃음을 주는 한 줄 | `dry_comic` |

`Space`는 이 실험 페이지 안에서 사용하는 단축키이며 다른 프로그램을 사용 중일 때 작동하는 운영체제 전역 단축키가 아닙니다. 방송 정보를 비우면 페르소나의 성격에 맞는 일반적인 한 줄을 만듭니다. 방송 정보는 참고 배경이며, 모델이 지금 화면을 보고 있거나 새로운 사건을 감지했다는 뜻은 아닙니다. 각 요청에는 버튼을 누른 시점의 페르소나와 방송 정보가 담깁니다.

버튼을 누르지 않으면 모델을 호출하지 않습니다. 요청이 진행 중일 때의 추가 입력이나 너무 빠른 연속 입력은 요청을 쌓지 않고 거부합니다. 받아들인 버튼 입력마다 생성 요청은 한 번이며 자동 재시도나 mock 전환은 없습니다. 기본 연속 입력 간격은 1초이고, 너무 늦은 결과는 표시하지 않습니다.

## 실제 모델 연결하기

서버를 실행하는 컴퓨터의 환경변수에 `GEMINI_API_KEY`를 설정합니다. `GOOGLE_API_KEY`도 지원합니다. 키는 브라우저 입력란이나 소스 코드에 넣지 않습니다. Bash에서는 다음처럼 키 값을 명령 기록에 남기지 않고 입력할 수 있습니다.

```bash
read -r -s -p "Gemini API key: " GEMINI_API_KEY
export GEMINI_API_KEY

python -m apps.web --provider gemini --model gemini-3.5-flash-lite --output runs/manual_real
```

Windows에서는 사용하는 셸의 환경변수 설정 방식을 사용한 뒤 같은 `python -m apps.web ...` 명령을 실행합니다. 인증이 없으면 서버 시작 단계에서 오류가 나며, 실제 호출에는 모델 API 사용 요금이 발생할 수 있습니다.

Gemini 요청에는 선택한 페르소나·방송 정보·최근 채팅이 텍스트로 들어갑니다. 실제 모델은 방송 정보를 채팅의 맥락으로 사용하며, 입력된 정보만으로 알 수 없는 구체적인 사건을 만들어내지 않도록 지시합니다. 프레임, 영상 파일, 오디오와 영상 재생 시점은 모델에 전달하지 않습니다. 출력은 비어 있지 않은 100자 이하 한 줄로 검증합니다.

수동 생성 API의 입력 필드는 `client_request_id`, `persona`, `channel_context`, `clicked_video_s`, `video_session_id`입니다. 별도의 반응 종류나 상황·말투 필드는 사용하지 않습니다. 페르소나 ID와 최대 1,000자의 방송 정보는 서버에서 검증합니다.

**실제 API 연결, 한국어 드립 품질과 실제 AI 지연은 인증을 연결한 후 별도로 검증해야 합니다.** mock과 자동 검사는 요청 흐름을 확인하는 용도입니다.

## 지연 측정과 결과 파일

| 수치 | 측정 범위 |
|---|---|
| `button_to_display_ms` | 브라우저가 버튼 입력을 처리한 시점부터 채팅을 DOM에 넣은 시점까지. 요청 왕복·모델 응답·화면 요소 삽입을 포함 |
| `api_latency_ms` | 서버가 생성 처리를 시작한 뒤 결과를 얻기까지의 시간 |
| `generation_ms` | provider가 모델 호출에 쓴 시간. mock에서는 인위적인 대기를 포함 |
| `clicked_video_s`, `displayed_video_s` | 선택한 동영상의 입력·표시 시점 재생 위치. 실제 경과 시간을 뜻하지 않음 |

버튼 지연은 브라우저의 `performance.now()`로 계산하고 표시 확인을 서버에 돌려보냅니다. 브라우저 확인이 없으면 서버는 결과가 준비되었다는 사실만 기록하며 실제로 표시했다고 간주하지 않습니다. 이 수치는 **DOM 삽입까지의 시간**으로, 물리적인 화면 픽셀이 그려진 시점이나 방송 플랫폼에 도착한 시점까지 측정하는 것은 아닙니다.

`--output`으로 지정한 폴더에 다음 파일이 저장됩니다.

| 파일 | 내용 |
|---|---|
| `run.json` | 모델·설정·mock 여부·상태 및 지연 요약 |
| `events.jsonl` | 요청 당시 페르소나·방송 정보, 생성 텍스트, 시점, 표시 확인·제외·오류 기록 |
| `events.csv` | 표로 확인할 수 있는 생성 기록 |

실행 중 [http://127.0.0.1:8765/api/export](http://127.0.0.1:8765/api/export)에서도 JSONL 기록을 내려받을 수 있습니다. 수동 모드는 패널에서 영상과 채팅을 함께 보여주며 결과 MP4를 별도로 렌더링하지 않습니다.

주요 선택 옵션은 `--port`, `--cooldown`, `--max-age`, `--timeout`, `--mock-delay`입니다. 전체 옵션은 `python -m apps.web --help`로 확인합니다. 검사 실행은 다음과 같습니다.

```bash
python -m unittest discover -s tests -v
```

아래는 이전 `experiments/replay.py` 기반 자동 분석 실험의 설명입니다. **현재 버튼 모드를 실행할 때 아래의 영상 추출·자동 판단 단계는 사용하지 않습니다.** 비교와 재현을 위해 기존 코드와 사용법을 보관합니다.

## 영상 하나로 검증하는 AI 라이브 채팅 실험

녹화 영상 한 편을 **실제 시간의 1배속으로 재생하면서**, AI가 언제 반응하고 어떤 한국어 드립을 만드는지 측정하는 CLI 데모입니다. 우선 확인할 것은 **상황을 제대로 이해하는지, 드립이 괜찮은지, 타이밍이 늦지 않는지**입니다.

현재 범위는 영상 파일 입력 → 과거 화면·소리 관찰 → `WAIT` / `REACT` 판단 → 채팅 표시 시점 기록 → 결과 영상 생성입니다. 데스크톱 화면 캡처, 방송 플랫폼 채팅 전송, 제품용 웹 화면은 다음 단계입니다. 생성된 `report.html`은 실험 결과를 확인하는 보고서입니다.

**검증 상태:** 합성 영상과 mock으로 실행 흐름을 확인할 수 있습니다. Gemini 연결 코드는 공식 REST 문서에 맞춰 작성했지만, API 키를 사용한 실제 모델 호출·지연·한국어 유머 품질은 아직 검증하지 않았습니다. mock 결과를 실제 AI 성능으로 해석하면 안 됩니다.

## 1. 실행 준비

필요한 환경은 Python 3.10 이상, `ffmpeg`와 `ffprobe`, Python 패키지 `numpy`, `Pillow`, `aiohttp`입니다. FFmpeg 프로그램 두 개가 `PATH`에 있어야 합니다.

프로젝트 폴더에서 실행합니다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
ffmpeg -version
ffprobe -version
```

Windows에서는 가상환경 활성화 명령을 사용하는 셸에 맞게 바꾸세요. 한글 채팅을 결과 MP4에 정확히 표시하려면 Noto Sans CJK KR 등 한글을 지원하는 `.ttf` / `.ttc` 글꼴을 준비하고 `--font`로 지정할 수 있습니다. HTML과 JSON에는 원래 유니코드 텍스트가 보존됩니다.

## 2. API 키 없이 흐름부터 확인

```bash
python -m experiments.make_fixture --output experiments/samples/fixture.mp4 --duration 18

python -m experiments.replay run experiments/samples/fixture.mp4 \
  --provider mock \
  --mock-delay 0.2 \
  --cooldown 4 \
  --duration 18 \
  --output runs/mock_demo
```

합성 영상은 직접 만든 애니메이션과 전자음입니다. 실제 방송인이나 음성이 아니며 `SYNTHETIC TEST` 표시가 들어갑니다. 함께 생성되는 `fixture.events.json`은 사람이 시점을 대조하기 위한 자료이며 모델 입력으로 사용하지 않습니다.

mock은 마지막으로 관찰한 화면의 우세한 색이 바뀌면 미리 정한 문장을 반환합니다. 실제 장면 이해나 한국어 드립 생성은 하지 않습니다. `--mock-delay 0.2`는 **인위적으로 넣는 0.2초 대기**이며 AI 응답 속도가 아닙니다. 결과에도 `PIPELINE TEST / MOCK — NO AI LATENCY RESULT` 표시가 계속 유지됩니다.

이 예시에서는 합성 영상의 두 장면 전환을 모두 확인하기 위해 채팅 간격을 `--cooldown 4`로 줄였습니다. 일반 실행의 기본값은 6초입니다.

## 3. 실제 영상으로 Gemini 실행

먼저 본인 컴퓨터의 환경변수 `GEMINI_API_KEY`에 API 키를 설정합니다. `GOOGLE_API_KEY`도 지원합니다. 키를 채팅, 소스 코드, 결과 파일에 넣지 마세요. Bash에서는 키 값이 명령 기록에 남지 않도록 다음처럼 직접 입력할 수 있습니다.

```bash
read -r -s -p "Gemini API key: " GEMINI_API_KEY
export GEMINI_API_KEY
```

그다음 본인의 데모 영상을 지정합니다.

```bash
python -m experiments.replay run /path/to/demo.mp4 \
  --provider gemini \
  --model gemini-3.5-flash-lite \
  --mode joint \
  --duration 60 \
  --output runs/gemini_joint
```

기본값이 `gemini`, `gemini-3.5-flash-lite`, `joint`이므로 해당 옵션은 생략할 수 있습니다. 영상 시작부터 최대 60초를 사용하며, 영상이 더 짧으면 전체 길이만 사용합니다. 매 실행에는 새로운 출력 폴더를 지정하세요. 키가 없거나 API 호출에 실패하면 오류를 기록하며, mock으로 자동 전환하지 않습니다. Gemini 실행에는 선택한 모델의 API 사용 요금이 발생할 수 있습니다.

이 초기 버전은 첫 영상 프레임이 파일 타임라인 0에 있는 일반적인 클립을 대상으로 합니다. 오디오보다 영상 트랙이 늦게 시작하는 등 초기 오프셋이 있는 파일은 결과 화면이 앞당겨지는 것을 막기 위해 거부합니다. 그런 파일은 트랙 시작 시점을 정규화한 클립을 먼저 준비해야 합니다.

한글 글꼴을 직접 지정하는 예시입니다.

```bash
python -m experiments.replay run /path/to/demo.mp4 \
  --duration 60 \
  --output runs/gemini_with_font \
  --font /path/to/NotoSansCJK-Regular.ttc
```

`--no-render`를 추가하면 MP4 렌더링을 건너뜁니다. 영상 전처리와 추론, 로그·보고서 생성은 수행합니다. 모든 CLI 옵션은 `python -m experiments.replay run --help`에서 확인할 수 있습니다.

## 4. 판단과 드립을 한 번에 만들까, 나눠 만들까?

| 모드 | 동작 | 비교할 점 |
|---|---|---|
| `joint` — 기본 | 화면·소리를 받은 모델이 판단과 드립을 한 번에 반환 | 요청 한 번으로 반응까지 완료 |
| `split` | 화면·소리로 판단한 뒤 `REACT`일 때만 글쓰기 모델 호출 | 판정 모델과 드립 모델을 따로 바꿀 수 있지만 반응에는 요청 두 번 필요 |

같은 영상에서 분리 모드를 비교합니다.

```bash
python -m experiments.replay run /path/to/demo.mp4 \
  --provider gemini \
  --model gemini-3.5-flash-lite \
  --mode split \
  --writer-model gemini-3.5-flash-lite \
  --duration 60 \
  --output runs/gemini_split
```

`--writer-model`을 생략하면 판단과 같은 모델을 사용합니다. 분리 모드의 글쓰기 단계에는 판단 모델이 만든 사건 설명과 최근 채팅을 전달합니다. 그 설명에서 빠진 장면 정보는 글쓰기 모델도 알 수 없습니다. 따라서 이 비교는 **요청 단계 수와 정보 전달 방식이 함께 달라지는 실험**입니다.

출력 구조는 아래와 같습니다. 다음 JSON은 형식 설명용 예시이며 실제 모델 실행 결과가 아닙니다.

```json
{
  "action": "REACT",
  "event": "물건을 잡으려다 다시 떨어뜨림",
  "evidence_frame_ids": ["f000045"],
  "comment": "중력이 오늘 유독 적극적이네 ㅋㅋ"
}
```

`WAIT`일 때 `comment`는 빈 문자열입니다. 시각적 근거는 입력에 포함된 프레임 ID만 인용할 수 있습니다. 소리만 근거로 삼은 경우 프레임 목록이 비어 있을 수 있습니다. 스키마 검사는 출력 형식을 확인하며, 실제 장면 이해와 드립의 적절함은 사람이 평가해야 합니다.

## 5. 실시간 영상은 어떻게 처리하나?

영상 전체를 모델에 먼저 보여주지 않습니다. 파일을 미리 디코딩한 뒤, 측정 시작 시각부터 흐르는 재생 시계에 따라 **그 시점까지 실제로 나온 프레임과 오디오 샘플만** 관찰하도록 제한합니다. 영상 전처리와 마지막 결과 렌더링은 지연 측정에서 제외합니다.

화면의 간단한 밝기 변화와 짧은 오디오 구간의 음량 변화를 후보 신호로 사용합니다. 크게 변했다는 사실만으로 드립을 확정하지 않고, 모델이 최근 맥락을 보고 `WAIT` / `REACT`를 결정합니다. 조용하지만 의미 있는 순간도 관찰하도록 주기적인 요청을 함께 사용합니다.

기본 실험 설정은 다음과 같습니다. 최적화된 권장값이 아니라 첫 비교를 위한 시작값입니다.

| 항목 | 초기값 |
|---|---|
| 주기적인 관찰 요청 | 2초 간격, 변화 신호도 사용 |
| 모델에 전달하는 최근 맥락 | 최대 4초 |
| 한 요청의 화면 수 | 최대 6장 |
| 표시한 채팅 사이의 최소 간격 | 6초 |
| 응답 완료 때 입력 관찰 시점부터 허용하는 최대 경과 시간 | 5초 |
| 기본 실험 길이 | 영상 시작부터 최대 60초 |

처리 중에는 오래된 요청을 무한히 쌓지 않고 최신 대기 입력만 남깁니다. 이미 늦은 응답, 너무 잦은 채팅, 중복 문장은 표시하지 않습니다. 표시에서 제외한 결과도 로그에는 남습니다. API 오류와 시간 초과는 자동 재시도로 숨기지 않습니다.

이 방식으로 확인하는 것은 파일 재생 환경의 관찰·추론·채팅 타이밍입니다. 실제 화면 캡처, 마이크 수집, 방송 송출, 플랫폼 채팅 전달 지연은 포함되지 않습니다. 짧은 사건이 관찰 간격 사이에 지나가거나, 4초보다 긴 대화 맥락이 필요한 경우에는 놓칠 수 있습니다.

## 6. 결과 파일과 지연 수치 읽기

| 파일 | 내용 |
|---|---|
| `run.json` | 실행 설정, 사용 모델, mock 여부, 요약 |
| `events.jsonl` | 요청별 판단, 근거, 텍스트, 타임스탬프, 표시·제외 상태 |
| `events.csv` | 표로 확인하기 위한 요청별 로그 |
| `report.html` | 영상 및 요청 기록을 확인하는 보고서 |
| `replay.mp4` | 원본 영상·소리와 실제 표시 시점에 맞춘 채팅. `--no-render`이면 생략 |

**모델 응답 시간과 사건에서 채팅까지의 지연은 다릅니다.**

| 필드 | 의미 |
|---|---|
| `input_cutoff_video_s` | 모델이 볼 수 있었던 입력의 마지막 허용 시점 |
| `api_latency_ms` | 추론 요청 시작부터 결과 수신까지의 소요시간. `split`은 필요한 두 단계 포함 |
| `snapshot_age_ms` | 입력 마지막 허용 시점 → 응답 완료까지의 경과 시간 |
| `decision_ms` | `joint`에서는 판단과 글쓰기를 포함한 단일 모델 호출 시간. `split`에서는 판단 단계 시간 |
| `generation_ms` | `split`의 글쓰기 호출 시간. `joint`의 0은 분리 측정할 수 없다는 뜻 |
| `displayed_video_s` | 채팅을 실제로 표시한 재생 시점. 미표시 결과는 `null` |
| 실제 사건 → 채팅 지연 | 사람이 해당 드립과 원본 사건을 연결한 후 `displayed_video_s - 사건 시점`으로 계산 |

`snapshot_age_ms`를 사건 발생부터의 지연이라고 부르면 안 됩니다. 사건이 입력 구간의 앞부분에서 발생했거나 관찰 요청을 기다렸다면 실제 지연은 더 길 수 있습니다. 전체 JSON이 수신되고 검증된 뒤 채팅을 표시하므로, 이 실험은 첫 토큰이 나온 시점도 측정하지 않습니다.

표시 상태에는 `displayed`, `wait`, `expired`, `cooldown`, `duplicate`, `invalid`, `error`, `after_end`가 있습니다. 빠른 성공 응답만 보지 말고 오류·만료·누락도 함께 확인하세요. mock의 모든 시간 수치는 해당 컴퓨터에서 실행한 파이프라인과 인위적 대기를 나타냅니다.

## 7. 첫 번째 품질 평가

1. 같은 데모 영상에서 **5~10개 순간**을 사람이 표시합니다. 반응할 만한 사건과 침묵이 자연스러운 구간을 모두 포함하세요. 사건 시작, 상황을 이해할 수 있게 된 시점, 기대하는 반응을 간단히 적습니다. 이 정답표는 모델에 전달하지 않습니다.
2. `joint`와 `split`을 같은 길이와 설정으로 각각 실행합니다. 한 번의 결과만으로 우열을 정하지 말고 동일 조건으로 몇 차례 반복합니다.
3. 표시된 드립마다 **상황 일치 여부, 자연스러움, 재미 1~5점, 너무 늦었는지, 반복됐는지**를 평가합니다. 가능하면 방송을 볼 사람 두 명이 독립적으로 채점합니다.
4. 적절하게 반응한 채팅의 비율, 표시할 만한 사건을 놓친 비율, 사람과 매칭한 사건→채팅 지연을 비교합니다. 요청 수·토큰 사용량, 오류·만료 수와 원본 사례도 함께 봅니다.
5. 먼저 잘못 이해한 장면과 재미없는 드립을 고치고, 그다음 관찰 간격·맥락 길이·모델·표시 간격을 바꿉니다. 5~10개 사건은 사례 검토용이며 안정적인 p95 성능 주장에는 충분하지 않습니다.

### 사람이 확인한 사건과 채팅을 연결하기

실제 원본을 보며 `annotations.json`에 사건을 적고, `events.jsonl`의 표시된 채팅 중 해당 사건에 적절한 반응이라고 확인한 요청을 `matches.json`에 연결합니다. 아래 시점과 ID는 **형식 설명용 예시**이므로 실제 평가 값으로 교체해야 합니다.

`annotations.json`:

```json
{
  "events": [
    {
      "event_id": "event_01",
      "onset_s": 12.0,
      "observable_s": 12.5,
      "valid_until_s": 17.0,
      "description": "물건을 다시 떨어뜨리는 상황을 알아볼 수 있는 순간"
    }
  ]
}
```

`matches.json`:

```json
{
  "reviewed_by_human": true,
  "matches": [
    {
      "request_id": "events.jsonl에서_확인한_request_id",
      "event_id": "event_01",
      "judgment": "appropriate"
    }
  ]
}
```

`onset_s`는 사건 시작입니다. 선택 항목인 `observable_s`에는 결과나 말의 뜻을 알 수 있게 된 시점을, `valid_until_s`에는 반응이 여전히 자연스럽다고 보는 마지막 시점을 적습니다. 말을 끝까지 들어야 이해하는 농담처럼 사건 시작과 이해 가능한 시점이 다를 때 구분해서 평가할 수 있습니다.

```bash
python -m experiments.replay score runs/gemini_joint \
  --annotations annotations.json \
  --matches matches.json
```

결과는 `human_review.json`에 저장됩니다. 사람의 확인 표시가 없거나, 표시되지 않은 채팅이거나, 모델 입력이 사건을 이해할 수 있는 시점보다 앞서 있으면 유효한 매칭으로 받아들이지 않습니다. 이 명령은 사람이 선택한 사례의 타이밍을 계산합니다. 재미·적절함·전체 사건의 재현율을 자동으로 판정하지 않습니다.

이 결과가 괜찮으면 입력 부분을 화면·마이크 캡처로 바꾸고 데스크톱이나 웹으로 감쌀 수 있습니다. 나중에 쌓인 `WAIT` / `REACT` 평가 데이터로 더 작은 판단 모델을 학습하는 것도 가능합니다. 예를 들어 FunctionGemma는 텍스트 전용 함수 호출 모델이므로, 사용하려면 별도의 영상·오디오 인식 단계에서 만든 관찰 정보를 입력해야 합니다. 현재 데모에는 Mamba나 별도의 소형 판단 모델 학습을 넣지 않았습니다.
