# 화면 AI 비용 비교 계획 (2026-10-31, 실행 전 고정)

범위는 `experiments/realtime_video/`입니다. 기존 앱·백엔드·설치 파일, 기본 모델, UI 설정은 변경하지 않습니다. 실제 방송 녹화본이 제공되지 않아 이번 비교에는 직접 만든 무음 합성 게임 장면을 사용합니다. 사람 방송에서의 재미·말투 품질을 검증했다고 해석하지 않습니다.

## 비교 조건

| 조건 | 모델 | 입력 선택 | 사전 호출 생략 |
|---|---|---|---|
| large_6 | gpt-realtime-2.1 | 1초 간격 6장 | 없음 |
| mini_6 | gpt-realtime-2.1-mini | 동일한 6장 | 없음 |
| mini_2 | gpt-realtime-2.1-mini | 첫 장과 마지막 장 | 없음 |
| mini_change_2 | gpt-realtime-2.1-mini | 화면 차이가 가장 큰 인접 2장 | 변화가 작으면 생략 |

6개 장면을 조건별 2회 반복합니다. 모든 조건은 같은 1280×720 JPEG, 같은 페르소나·프롬프트·상황 설명·출력 한도를 사용합니다. 각 판단은 새 연결에서 시작하여 서로의 대화나 결과가 섞이지 않게 합니다. 이전 채팅은 모두 비웁니다. 조건 실행 순서는 장면·반복마다 순환합니다. 장면 정답과 설명은 AI 입력에 넣지 않습니다.

입력 선택과 실행 순서는 결과를 보기 전에 고정합니다. 로컬 변화 감지는 RGB 160×90 축소 이미지의 평균 절대 차이(0~1)를 사용하며 임계값은 0.0005입니다. 최신 6장 안에서만 비교하므로 미래 화면은 보지 않습니다. 단순 움직임도 감지될 수 있으므로 이 감지는 의미 있는 사건을 판단하는 AI를 대체하지 않습니다.

## 장면 및 사전 정답

- `still`: 점수판 정지. WAIT.
- `lead_change`: 빨간 팀 점수가 1→4로 올라 파란 팀 3점을 추월. REACT.
- `health_drop`: 체력이 100→20으로 감소. REACT.
- `transient`: 중간에 DEFEAT가 잠깐 표시되고 원래 화면으로 복귀. REACT. 첫·마지막 2장만으로는 사건이 관찰되지 않는 의도적 누락 검사.
- `motion_only`: 점수·체력 변화 없이 도형만 이동. WAIT.
- `small_score`: 작은 점수 표시 0→1 변화. REACT. 화면 변화 감지가 작은 정보를 놓치는지 검사.

## 측정과 판정

- 형식 유효율, WAIT/REACT 일치율, 비사건 오반응, 사건 누락을 별도로 기록합니다. 실패와 생략을 분모에서 빼지 않습니다.
- REACT의 근거 프레임이 입력에 존재하는지는 기존 파서로 검사합니다. 사건을 직접 보여주는 프레임인지는 별도 지표로 기록합니다.
- 코멘트 전체를 남겨 장면과의 관계·근거 없는 소리/행동 주장·한국어 말투를 검토할 수 있게 합니다. 정답 행동 일치만으로 사실성·자연스러움에 합격 판정을 내리지 않습니다.
- API `response.done.usage`로 이미지/텍스트/캐시/출력 토큰을 읽고 공식 단가로 계산합니다. 형식 오류가 난 유료 응답도 비용에 포함합니다. 사용량을 못 받으면 0원으로 처리하지 않고 실험을 중단합니다.
- 지연은 분석 요청부터 응답 처리까지이며, 실제 방송 이벤트 발생→화면 표시 지연이 아닙니다. 새 연결을 여는 시간은 분석 지연에서 제외합니다.
- 생략 조건은 실제 API를 호출하지 않습니다. 절감률은 같은 장면 묶음의 전체 비용으로 비교하며 호출당 비용도 따로 제시합니다.
- 10초 간격과 채팅 직후 호출 생략은 녹화 타임라인에 대한 별도 오프라인 스케줄 검사입니다. 이 결과를 실제 방송의 사건 감지율이나 실측 시간당 비용으로 표시하지 않습니다.

## 예산·종료 조건

유료 요청은 최대 48회, 재시도는 하지 않습니다. 기본 예산은 $1이며 새 요청 전 $0.25의 보수적인 여유를 남겨둡니다. 공급자의 실제 청구액을 강제로 제한하는 장치는 아니며, 로컬 관측 비용과 요청 수를 제한합니다. 인증·연결 문제, 사용량 누락 또는 한도에 도달하면 중단하고 부분 결과를 보존합니다. 합성 자료만 전송하며 사용자 화면·음성을 캡처하지 않습니다.

이 소규모 탐색 비교로는 운영 모델을 자동 변경하지 않습니다. 저비용 조건의 장면별 실패와 원문 응답을 확인한 뒤 실제 방송 녹화본으로 검증할 후보를 고릅니다.

단가 근거: [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Realtime usage](https://developers.openai.com/api/docs/guides/voice-latency-cost).

## 사용자 요청에 따른 오류 수정 후 재검증

첫 비교는 48개 조건 중 42회 호출했고, 추가 진단 2회로 완료했습니다. 자유 텍스트 형식의 불안정을 확인한 뒤 사용자가 오류 수정을 요청했습니다. 이전 결과는 각 `runs/cost_*/plan.md`와 `results.json`에 그대로 보존합니다.

수정은 자유 텍스트 JSON 대신 `submit_screen_decision` 함수 호출을 지정하고, 완료된 함수 인자만 읽으며 메시지·중간 설명을 판정에서 제외하는 것입니다. 함수 인자도 같은 의미 검증을 통과해야 하며 빈 결과를 WAIT로 바꾸거나 재시도하지 않습니다.

수정 후 단계는 Mini의 정지/체력 장면 2회 사전 점검과, 같은 4조건×6장면의 1회 반복으로 제한합니다. 합계 최대 24회 호출, 별도 로컬 예산 $1 이내입니다. 모델별 프롬프트와 함수 스키마는 동일하며, 입력·장면 정답·프레임 선택 규칙을 바꾸지 않습니다. 형식 성공과 사건 감지를 별도 지표로 계속 기록합니다. 1회 반복이므로 모델 품질의 통계적 우열을 주장하지 않습니다.
